2. Touch & Interaction CRITICAL

Min size 44×44px · 8px+ spacing · Loading feedback. Avoid: reliance on hover only, instant 0ms state changes.

Touch target size is platform-specific — and the web minimum is lower than you'd thinkHighNEW NUANCE

The earlier review's "44×44px" rule is the iOS number. On the web, WCAG 2.2 AA's actual floor is 24×24 CSS px (with spacing/exception clauses) — useful context if 44px ever feels like a hard sell for a tight header, but 44px is still the better target for a senior-skewed audience like this app's.

DoiOS 44pt / Android 48dp for native; web minimum is 24 CSS px + WCAG exceptions, but aim higher for senior users
Don'tTreat one number as universal across platforms, or ship w-6 h-6 icon buttons
In this project: the five ~28×28px top-bar icons, and the 41 sub-44px tap targets counted on Ministry Sign-ups.

A warning bar that auto-dismisses is the wrong pattern for a form errorMediumCLARIFIES EARLIER FLAG

Auto-dismiss after 3–5s is correct for a toast (e.g. "Message sent") — but a required-field error is not a toast, it's validation feedback, and it should stay until the user fixes the problem. This is why Top-5 fix #2 is right to move it to the top and keep it visible, not just relocate the same disappearing bar.

DoAuto-dismiss toasts for non-critical info after 3–5s; keep validation errors visible until resolved
Don'tUse the same transient-toast pattern for "you can't submit this form"
