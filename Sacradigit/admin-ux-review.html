1. Can I trust what the screen says? Critical

An office dashboard is only useful if every number on it is real.

1.1 The Dashboard's "Cloud Status" and storage figures are fixed text, not real data HighBoth

"Firestore: Operational", "Storage Bucket 6.8 / 10 GB", "Last Backup: 2 hrs ago" and "Auth Service: Operational" are written into the page, so they never change. The app doesn't even use Firestore; it runs on AWS Amplify. If the storage really fills up or a backup fails, this panel will still say everything is fine.

3. Head Admin role High

The Head Admin's decisions email parishioners and can't be taken back from the screen.

3.1 Approve and Release act on one tap, with no confirmation and no undo HighHead AdminSecretary (Release)

Tapping Approve immediately marks the request approved and emails the parishioner that the certificate is ready. Release is the same. A slip of the finger, or the wrong row on a long list, can't be undone, and the parishioner has already been emailed.

5. Forms & feedback Medium

Long data-entry forms (certificate generation, walk-in requests) are where office staff spend their time.

5.1 Warnings are a red bar at the bottom that vanishes after 3 seconds MediumBoth

Each admin page has its own copy of showToast() (10+ copies) that fades after 3 seconds, errors included. A message like "Only the Head Admin can delete records" or "Couldn't update the request" disappears before it's read. The parishioner side now keeps errors until closed.

7. Design direction Optional

From --design-system. The first query ("parish office admin records dashboard") returned an off-target event-landing style, so I retried once with "admin dashboard records management data-dense".

Style match: "Data-Dense Dashboard"

Best for operational and enterprise dashboards: data tables, KPI cards, minimal padding, maximum data visibility. Accessibility needs: 4.5:1 text contrast, keyboard use, visible focus, reduced motion. Anti-patterns to avoid: ornate design, no filtering. For SacraDigit that means keeping the maroon, navy and gold brand, but tighter: one title per page (6.2), real buttons in rows (6.1), and the sacred-art hero only on the Dashboard.

The suggested font pairing (Fira Sans / Fira Code) is optional. The current Inter font is already a good data-screen font.

Source: styles.csv + typography.csv + colors.csv via --design-system (retry).
